## 2026-10-01 (1) — 상세는 히스토리에도 하나만: 열린 채 다른 상세를 열면 `replaceState` (B59) · 창 크기 변경은 다시 놓기 (B60)

프론트 실측(데스크톱 1440px): 제주 상세 → 후쿠오카 상세 → `×` 를 누르면 **제주가 다시 열린다.** `×` 가 `history.back()` 이고(B58 — 그 전엔 `×` 가 사이트를 떠났다) 바로 앞 항목이 제주라서.
스펙은 이미 둘 다 말하고 있었다 — 「`×` 는 카드만 닫힌다」·「뒤로가기는 상세만 닫힌다 · `#{허브}`」(§CH4). 구현이 상세마다 `pushState` 를 쌓아 **둘 다 어겼다.**
**결정(프론트 (가) 채택)**: 상세가 열려 있으면 다음 상세는 `replaceState`. 화면의 「동시에 하나만」을 히스토리에도 건다. `×` 는 `history.back()` 그대로 — B58 을 안 건드린다.
대가: A→B 로 옮겨 본 사람이 뒤로가기를 누르면 A 가 아니라 지도로 간다. A→B 는 **같은 자리에서 대상만 바꾼 것**이라 받아들인다(피드에 A 카드가 그대로 있어 한 번 누르면 돌아온다).
**기각 — (나) `×` 가 `history.go(-n)`**: `n` 을 세는 상태가 새로고침·딥링크에서 사라진다 — 조용히 틀릴 자리. **기각 — (다) 그대로**: 스펙 두 줄과 화면이 어긋난 채 남는다.
**B60**: 상세를 연 채 창 크기를 바꾸면 카드가 핀에서 세로 150px 떨어진다(프론트 실측 — 백로그의 「가로 142px」는 PH5c·CH8 뒤로 낡았다). **닫지 않고 다시 놓는다.**
「지도를 움직이면 상세가 닫힌다」(09-29 사용자)의 이유는 따라다니면 어지럽다는 것이고, 창 크기 변경은 한 번의 점프라 그 이유가 닿지 않는다 — 규칙을 늘리지 않고 불변식(카드는 자기 핀을 가리킨다)을 지킨다.
**순서**: B59·B60 의 「PH5b 결론 뒤로」 보류는 09-28 「모바일 최후미, 데스크톱 먼저」(사용자)로 풀렸다 — 둘 다 데스크톱에서 재현된다.

## 2026-10-01 (2) — 키보드·낭독기: 「피드가 곧 지도」 유지, 자유 줌·지역바에 맞춰 갱신 (B11) · 포커스는 두 겹 · 보이지 않는 문자열 채움

프론트 착수 실측(1440px, 접근성 트리): 조작 88개 중 탭으로 닿는 것 30개. 카드 24·핀 24·지역 칩 10 이 전부 0. 딜에 닿는 키보드 길은 hero 버튼 하나. `aria-live` 0, 예산 슬라이더 이름 없음, `Esc` 로 상세 못 닫음.
프론트가 「지도는 그림, 피드가 정본」을 **새 모델로 통지**했는데, **§CH6 에 2026-09-01 확정으로 이미 있던 문장**이다(「핀은 카드의 시각적 표현 · 피드가 곧 지도」). 어제 COPY §8 에 이어 이틀 연속 — 스펙을 열기 전에 지었다.
**유지**: 지도 `role="img"` · 핀 `aria-hidden` · 카드가 조작 대상 · 상세 포커스 안으로/`Esc`/복귀. PH5c 「지도를 액티브하게」와 어긋나지 않는다 — 그건 포인터 조작이고, 키보드의 뷰 이동은 지역바와 `＋－` 가 맡는다.
**갱신(지도 모델이 바뀌어서)**: 단계바(radiogroup) → **지역바 = 정지점 하나 + `←→` + `aria-pressed`**(칩은 이동이지 상태 선택이 아니고, 켜진 칩이 없을 수 있다). 칩 10개를 각각 정지점으로 두면 피드 앞에 10번이 더 쌓인다.
**새로**: 불변식 「키보드만으로 모든 딜에 닿는다」(여집합 검사) · 건너뛰기 링크 · 카드 포커스 = 호버(DESIGN 「호버에만 있는 기능을 두지 않는다」) · 개수 변화는 보이는 부제를 `role="status"` 로(새 문자열 0) · 상세 DOM 은 지도 img 밖.
**포커스 표시**: `:focus-visible` 두 겹(흰 2px + `--ink` 2px). 백로그의 「focus 가 안 보인다」는 프론트 실측으로 정정 — 크롬 기본 링은 뜬다, **우리가 안 정했을 뿐**이다. 한 색 링은 코랄·`--ink` 칩·사진 중 어딘가에서 묻혀 두 겹으로.
**문자열**: COPY §2 「보이지 않는 문자열」 표를 채웠다. 프론트 예시 「…왼쪽 피드에 있습니다」는 방향어·합니다체라 안 쓴다.
**기각 — 핀 24개를 정지점으로**: 같은 목록을 두 번. **기각 — 화살표로 지도 끌기**: 지도를 정지점으로 만들어야 하고 img 와 충돌, 지역 칩이 덮는 뷰와 겹친다. **기각 — 카드 통째 `aria-label`**: 보이는 글자와 갈린다.

## 2026-10-01 (3) — 탭 순서는 DOM = 보이는 순서, 조작에 먼저 닿는 길은 건너뛰기 링크 둘 (기획이 쓴 두 줄이 부딪쳤다)

(2)에서 기획이 §CH6 표 한 칸에 「조작이 먼저, 결과가 뒤(필터 → 정렬 → 지역바 → 줌 → 피드)」와 「DOM 순서 = 보이는 순서」를 같이 적었다. **레이아웃을 재지 않고 나열했다.**
프론트 실측: 피드(340px)가 왼쪽·먼저, 지역바·줌·필터는 오른쪽 무대 안의 `absolute`. 보이는 순서로 읽으면 피드가 먼저라 **두 줄을 동시에 못 지킨다.**
**결정(프론트 (다) 채택)**: DOM 은 그대로(헤더 → 정렬 → 피드 카드 → 지역바 → 줌 → 필터). 첫 Tab 에 건너뛰기 링크 **둘** — `목록으로 건너뛰기` · `지역·필터로 건너뛰기`.
**기각 — (가) 컨트롤을 피드 앞으로**: 눈으로 따라가는 키보드 사용자의 포커스가 좌우로 튀고, 지역바를 무대 밖으로 빼면 피드 폭 340 의 손 사본이 CSS 에 생긴다. **기각 — (나) 건너뛰기 없이 그대로**: 지역바가 카드 24장 뒤.
**남는 대가**: 필터를 바꾼 뒤 결과(피드)는 DOM 에서 앞에 있다 — 낭독기는 부제 `role="status"` 로 개수를 듣지만, 카드로 가려면 되돌아가야 한다. 불편이 관찰되면 그때 본다.
**같이 확인된 것**(프론트 실측): 피드 부제는 지역 칩·필터·출발지 **모든 조작에서 바뀐다** → status 하나로 덮인다 · 상세 `#hc` 는 `svg.map` 의 형제라 img 밖 — 옮길 것 없다.
**교훈**: 순서를 스펙에 적을 땐 DOM·레이아웃을 재고 적는다. 「원칙 + 나열」을 한 칸에 쓰면 나열이 원칙을 어겨도 쓴 사람이 못 본다(함정 13 계열).
